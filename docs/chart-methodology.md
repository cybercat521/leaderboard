# Table30 V2 chart methodology

The README charts show the first five models in the official Table30 V2 API order. Both charts and the leaderboard are generated by `python3 update_leaderboard.py` from the same response. Python 3.11+ and the system `curl` are sufficient; no plotting packages are required.

## Primary sources

- [Official leaderboard JSON](https://robochallenge.cn/api/v2/leaderboard/leaderboard_table30_v2.json): overall rank and per-task `task_results[].success_ratio`.
- [Official V2 benchmark metadata](https://robochallenge.cn/api/v2/benchmark/benchmark_list.json): `benchmark_id = table30v2`, task names and `task_tag` arrays.
- [Official task pages](https://robochallenge.cn/task_detail/table30_v2?task_id=6dcb): task IDs and names. The same mapping is recorded in `table30_v2.py` because benchmark metadata does not contain IDs. The updater stops if the official set of task names changes.

The V1 mapping in `data.py` is unrelated to these charts and is not used.

## Capability radar

Each model has its own radar, arranged in one row, with an identical 0–100% scale. Six official capability tags cover at least three of the current tasks:

| API tag | Display label | 中文 | Current tasks |
|---|---|---|---:|
| bimanual | Two-hand | 双手协作 | 13 |
| precise3d | Precision | 空间精度 | 14 |
| manipulation | Manipulation | 物体操作 | 14 |
| temporal | Timing | 时序控制 | 6 |
| softbody | Soft-body | 柔性物体 | 7 |
| repeated | Repetition | 重复操作 | 12 |

These readable labels are editorial translations. They are six selected tags, not a new official capability taxonomy. Sparse tags (`simple-pick`: 1 task, `classification`: 2, `multiview`: 1), robot names and arm-count tags are not plotted. A task may have more than one capability tag.

For a model and capability, the plotted value is the arithmetic mean of task success rates over **all official tasks with that tag**. Tasks without a reported result contribute zero. This fixed denominator prevents partial evaluation from inflating a capability mean. It is a visualization aggregate, not a separate official ranking or score.

## Task heatmap

All 30 tasks are grouped by robot in the same order as the README. Values use official per-task success rates, multiplied by 100. An evaluated task with no successes is the zero end of the blue scale; an unreported task is blank. These are deliberately different. Light and dark images use a single blue sequential ramp with two-decimal percentage labels in evaluated cells. Unreported cells remain blank. The image omits a title and color legend; exact values also remain available in the CSV.

[Capability CSV](../data/table30-v2-capabilities.csv) contains the means. [Task CSV](../data/table30-v2-tasks.csv) contains the per-task values; a blank success-rate field means no result. CSV values retain four decimals; displayed success rates use two decimal places. [Task tags JSON](../data/table30-v2-task-tags.json) preserves all official tags, including the sparse tags omitted from the radar.

## Automatic updates

`.github/workflows/update_leaderboard.yml` runs daily at 07:00 UTC (15:00 Beijing time), on manual dispatch and when updater code changes on `main`. It commits README, SVG and CSV changes together. SVG rendering is deterministic, so unchanged data does not produce new image commits.

The API is served by a CDN that can reject some TLS handshakes. Requests try normal verified HTTPS, verified TLS 1.2, system `curl` and the official `www` hostname. Every request uses a unique query parameter and `Cache-Control: no-cache` to avoid stale CDN responses (the bare www URL previously returned a snapshot from 2026-10-01). Certificate verification stays enabled. If fetching, validation or chart generation fails, the job fails before writing outputs and no changes are committed. Model names are escaped before embedding into SVG and CSV.
