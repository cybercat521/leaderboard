# Table30 V2 chart methodology

The README charts show the first five models in the official Table30 V2 API order. Both charts and the leaderboard are generated by `python3 update_leaderboard.py` from the same response. Python 3.11+ and the system `curl` are sufficient; no plotting packages are required.

## Primary sources

- [Official leaderboard JSON](https://robochallenge.cn/api/v2/leaderboard/leaderboard_table30_v2.json): overall rank and per-task `task_results[].success_ratio`.
- [Official V2 benchmark page](https://robochallenge.cn/benchmark_detail/table30_v2) and its [metadata](https://robochallenge.cn/api/v2/benchmark/benchmark_list.json): all 30 task names and complete `task_tag` arrays were checked on 2026-10-29. The checked mapping is stored as a static input in [task tags JSON](../data/table30-v2-task-tags.json); the updater never fetches task metadata.
- [Official task pages](https://robochallenge.cn/task_detail/table30_v2?task_id=6dcb): task IDs and names. The same mapping is recorded in `table30_v2.py` because benchmark metadata does not contain IDs. Local validation checks the 30 IDs, names, robots and finite tag set. Future official task/tag changes require a deliberate local update.

The V1 mapping in `data.py` is unrelated to these charts and is not used.

## Capability radar

Each model has its own radar, arranged in one row, with an identical 0–100% scale. All nine official capability tags are plotted using their original names in both languages:

| Official tag | Tasks |
|---|---:|
| bimanual | 13 |
| precise3d | 14 |
| manipulation | 14 |
| temporal | 6 |
| softbody | 7 |
| repeated | 12 |
| simple-pick | 1 |
| classification | 2 |
| multiview | 1 |

The complete finite set contains 15 tags: these nine capabilities, four robot tags (`ALOHA`, `ARX5`, `DOS-W1`, `UR5`) and two arm-configuration tags (`single-arm`, `dual-arm`). Robot and arm tags remain in the static mapping but are not capability axes. `bimanual` and `dual-arm` are distinct official tags. Tasks may have multiple capability tags; axes covering only one or two tasks provide narrower evidence.

For a model and capability, the plotted value is the arithmetic mean of task success rates over **all official tasks with that tag**. Tasks without a reported result contribute zero. This fixed denominator prevents partial evaluation from inflating a capability mean. It is a visualization aggregate, not a separate official ranking or score.

## Task heatmap

All 30 tasks are grouped by robot in the same order as the README. Values use official per-task success rates, multiplied by 100. An evaluated task with no successes is the zero end of the blue scale; an unreported task is blank. These are deliberately different. Light and dark images use a single blue sequential ramp with whole-number percentage labels in evaluated cells. Unreported cells remain blank. The image omits a title and color legend; exact values also remain available in the CSV.

[Capability CSV](../data/table30-v2-capabilities.csv) contains the means. [Task CSV](../data/table30-v2-tasks.csv) contains the per-task values; a blank success-rate field means no result. CSV values retain four decimals; leaderboard and radar success rates use two decimal places, while heatmap cell labels are rounded to integer percentages. [Task tags JSON](../data/table30-v2-task-tags.json) preserves all official tags as a fixed input and is never overwritten by the updater.

## Automatic updates

`.github/workflows/update_leaderboard.yml` runs daily at 07:00 UTC (15:00 Beijing time), on manual dispatch and when updater code or the static task tags change on `main`. Only leaderboard data is fetched. It commits README, SVG and CSV changes together. SVG rendering is deterministic, so unchanged data does not produce new image commits.

The API is served by a CDN that can reject some TLS handshakes. Requests try normal verified HTTPS, verified TLS 1.2, system `curl` and the official `www` hostname. Every request uses a unique query parameter and `Cache-Control: no-cache` to avoid stale CDN responses (the bare www URL previously returned a snapshot from 2026-10-01). Certificate verification stays enabled. If fetching, validation or chart generation fails, the job fails before writing outputs and no changes are committed. Model names are escaped before embedding into SVG and CSV.
